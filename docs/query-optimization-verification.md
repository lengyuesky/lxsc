# 查询与前端优化验收

2026-09-29，开发基线 `693788a`。本轮落实项目审查中的六项建议；所有测试使用临时数据库、合成音源或本地 WAV，不读取或修改生产数据。

## 已实施行为

1. **分页与参数**：Subsonic 数量统一限制为 0–500，负数归零，非法整数字符串使用默认值；偏移非负，极大整数保留运算余量。零数量返回空列表，切片分页避免整数溢出。本地搜索和空搜索应用歌曲偏移，排序增加歌曲 ID 作为稳定次序。
2. **音源预算**：同一音源的多档音质共用最多 20 秒总预算；按剩余候选数与调用总期限分配时间，并预留媒体响应头阶段。超时停止该音源的进一步降级，健康备用源可以接替；普通音质错误仍按既有顺序降级。保留过载立即返回、调用取消、候选身份与缓存版本保护。
3. **资料库批量读取**：一条 SQL 合并用户收藏、自己及其他用户的公开歌单、最近 200 首播放记录；按歌曲 ID 去重，不再为每个歌单读取两次。请求内部复用资料库快照，向调用者返回独立切片。新增历史覆盖索引 `(user_id, track_id, played_at DESC)`，减少分组查询回表。
4. **本地子串索引**：SQLite FTS5 trigram 索引筛选三字符以上的非通配符关键词，再由原 LIKE 条件校验。短关键词、通配符和 NUL 保留原路径；空查询走更新时间／ID 索引。派生整数键避免依赖 tracks 的隐含 rowid，覆盖压缩后的更新；触发器在同一事务维护插入、修改、删除及回滚，首次初始化原子补齐旧数据。
5. **统计合并与边界**：只合并同用户、日期、范围及数据版本的在途请求，完成后立即移除；不引入陈旧统计缓存或每日汇总表。成功上报、用户改名和删除使后续请求使用新版本。全局 2 个执行、16 个排队、15 秒预算，超载明确返回 503。单个调用者取消不影响其他页面，最后一个等待者取消会停止实际查询；结果切片独立。性能接口新增 `listeningWorkload`，原 `listening` 耗时计数现在反映实际聚合查询。
6. **前端模块与 CSP**：备份、设置、导入、管理页面和公共显示函数独立，`app.js` 从 1046 行缩减到 403 行。备份与导入状态封装，退出清空备份输入；文件或密码改变取消旧检查，旧响应不能开启导入。移除内联事件，脚本按内容生成 SRI 和 CSP 哈希，禁止内联脚本、事件与 eval。保留动态样式及 HTTP(S) 图片／媒体所需权限，正常播放与原生表单下载保持兼容。

资料库和本地搜索使用现有只读池；`database.statistics` 保留接口名称，现反映这些读取与统计共同使用的最多 2 个连接。业务连接仍为单写连接。

## 合成测量

Linux/amd64，i5-13600K，Go 1.27.1；每组 20 次，重复三轮。搜索使用低命中率的四字关键词，最多返回 20 条，比较同一数据库上的完整结果读取；数据准备不计入耗时。

| 局部路径 | 原实现 | 优化后 |
|---|---:|---:|
| 一万首歌曲子串查询 | 4.71–5.82 ms | 0.097–0.227 ms |
| 十万首歌曲子串查询 | 17.31–28.99 ms | 0.567–0.649 ms |
| 一百个歌单、两千首歌曲 ID 汇总 | 6.48–7.42 ms | 2.95–3.30 ms |

统计并发验证：20 个同条件请求只执行一次实际聚合；完成后的下一次请求重新查询。不同用户、日期、范围和写入版本不合并。以上结果只反映合成局部查询，不包含真实音源、网络和音频传输，也不代表整体性能提升倍数；索引对大量结果命中的收益会降低，写入及磁盘占用有所增加。

```bash
GOTOOLCHAIN=go1.27.0 node scripts/licenses.mjs --check

```
