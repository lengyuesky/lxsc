# 功能保留优化验收

日期：2026-10-09。

## 修改范围

- 保留现有网页、Subsonic、调试、备份、统计、歌单订阅等功能；保留 `/api/admin/search` 及 `boardLimit`、`boardTrackLimit` 的兼容读写。
- 删除全仓库没有调用的 `Catalog.Remember`、`Catalog.BoardTracks`、`Catalog.HotSearch` 和 `Server.noop`。同步持久化、完整榜单与协议占位接口继续工作。
- 五个平台 SDK 入口取消未接入的评论、热搜、搜索联想导入；QQ 同时取消未接入的用户歌单导入。16 个模块不再进入 bundle，对应第三方源码和许可仍保留，来源摘要与修改记录同步更新。实际业务所用的 SDK 方法通过 goja 加载验证。
- 设置在持久化前统一校验整份补丁。未知字段、null、错误类型、无效模式／音质、越界或非整数数量都会失败；数据库失败也不发布内存值。继续接受原有十进制整数字符串、平台逗号列表和布尔格式；重复平台按原顺序规范化。

## 榜单任务边界

- 后台最多 3 个执行、32 个排队；先取得队列名额再创建任务，满载时不阻塞目录响应，也不留下失败或在途标记。
- 排队和等待用户请求空闲合计最多 45 秒；队列满或等待超时后，可由后续目录请求再次安排预热。
- 用户正在搜索或准备播放时暂缓启动后台榜单；后台逐页读取，前台最多并行 4 页。数量、顺序、去重及完整快照的规则不变。
- 实际整榜读取仍有 45 秒预算。页面取消只结束等待，服务退出则取消并等待后台队列、共享任务队列及实际读取，之后再关闭 SDK 和数据库。
- 原有旧快照立即返回、后台刷新、失败冷却及重启回放继续保留。性能接口的 `music.boardWarmup` 提供执行数、排队数、容量与拒绝数。

## 听歌统计

总计复用歌曲排行的聚合结果，并在取前 10 首之前进行窗口汇总。每个会话只属于一首歌，按歌曲聚合的会话数相加仍能保持跨日去重。活跃天数复用每日聚合；原始明细的范围聚合由个人查询的 3 次减为 2 次、全站查询的 4 次减为 3 次。

日期范围、排行顺序、未知时长、个人／全站隔离、只读事务快照及在途查询合并保持原语义。新增测试覆盖超过 10 首歌曲的总计、跨日会话、同一歌曲的多个用户与未知时长。

本次不清理、迁移或回填任何统计明细，也不改变备份格式。明细仍会随使用增长；长期归档和保留期限不在本次修改范围内。

## 合成测量

本机 Apple M6、Go 1.27.0；每组 10 次调用、重复 3 组，表中取三组的中位数。临时 SQLite 数据库包含 7 个用户、997 个歌曲 ID，收听记录分布在 30 天内；只测服务内统计调用，不访问真实音源。

| 收听记录数／查询范围 | 修改前 | 修改后 | 耗时减少 |
|---|---:|---:|---:|
| 1 万／个人 | 5.84 ms | 4.71 ms | 19.3% |
| 1 万／全站 | 37.76 ms | 26.73 ms | 29.2% |
| 10 万／个人 | 70.97 ms | 44.67 ms | 37.1% |
| 10 万／全站 | 573.78 ms | 409.23 ms | 28.7% |

SDK bundle 从 323,300 字节减为 282,941 字节，减少 40,359 字节（12.48%）。构建使用 Bun 1.3.14 和现有锁文件，没有升级依赖或开启压缩。

这些数值不代表生产整体性能提升；统计查询的 Go 分配量略增，实际收益取决于数据分布。统计存储没有缩减，不以固定机器耗时设置测试门槛。

复现统计基准：

```bash
GOTOOLCHAIN=go1.27.0 go test ./internal/db -run '^$' -bench '^BenchmarkListeningStatistics$' -benchmem -benchtime=10x -count=3
```
