# 安全边界与资源优化验收

2026-09-29，开发基线 `7947376`。本轮只修改源码、测试与开发配置，不更改生产数据、原有二进制或运行容器。

## 已实施范围

1. **封面代理**：将调试探测的公网地址策略抽取到 `internal/httpguard/outbound.go`，两处共享 DNS/IP 绑定、逐跳验证、TLS 校验和重定向限制。封面使用独立无代理客户端，最长 12 秒、最多 8 MiB、全局 8 路／每用户 2 路；仅按签名接受栅格图片，不沿用上游 Content-Type 或转发用户认证信息。
2. **认证与启动配置**：新库首次创建管理员必须显式提供至少 12 个字符且不同于用户名的密码，已有账号不被改写。Subsonic 保留密码、hex、token、API Key 兼容性，失败认证按账户／Key 摘要 20 次、IP 60 次每分钟限频；在途先预占，成功释放，超限返回带协议错误体的 429。配置解析错误不再被启动或健康检查忽略。
3. **代理信任**：默认不信任转发头；启用 `trust_proxy` 必须同时提供 `trusted_proxies` CIDR。只有连接对端在名单中才处理转发链，从右向左剥离可信代理，不接受客户端自填的首个 XFF。Cookie 的 Secure 位只取真实 TLS 或已验证的 HTTPS 标记。
4. **I/O 与媒体额度**：普通接口有正文、读取和响应期限，上传／备份采用不同预算；调试接口保留原有更严格策略。媒体传输另设全局 32 路／用户 4 路，和准备阶段分离。代理正文按每次读取／写入的 30 秒空闲截止保护，不设置整首音频的总时长。
5. **数据库**：新增 `playlist_tracks(track_id)`、`stars(kind,item_id)`、`history(track_id)` 索引；收藏专辑 JSON 引用集合改为非相关子查询，排除 null 后统一展开。清理不再隐含 `VACUUM`；显式管理员压缩要求 `confirm:true`、最多 5 分钟，和清理互斥。
6. **缓存与前端**：只入内存的歌曲不再构造数据库行／序列化 JSON。统一请求、用户管理、维护功能拆成独立脚本，用户列表和维护按钮使用事件绑定。静态资源支持内容版本、ETag、预生成 gzip；HTML 和无版本 URL 重新验证，匹配内容版本的资源长期缓存。
7. **交付检查**：统一 `scripts/check.sh` 指定源码包，避免扫描运行备份；CI 执行竞态检测、独立浏览器验收、基准结果归档。构建／发布同时等待普通检查和浏览器任务，原有 PR 权限隔离不变。Playwright 1.58.2 使用独立 npm 锁文件，不随运行镜像分发。

听歌统计汇总表、历史保留策略和更复杂的统计缓存未实施：这些属于需要真实数据规模支撑的扩容选项。没有更换前端框架，也没有在尚有内联事件的页面上强行启用严格 CSP。

## 升级注意事项

- 先备份。启动会自动建立新索引，耗时取决于现有数据量；没有清空或重建业务表。
- 已有用户无需再次提供初始化密码；现有弱密码不会被自动修改，管理员仍应自行改密。
- 旧配置只设置 `trust_proxy: true` 而未配置网段时，现在会明确拒绝启动。请填反代实际连接地址／网段，不要泛化为信任所有来源。反代须覆盖 `X-Forwarded-Proto` 并正确维护 XFF，保留并校验 Host。
- 封面代理不再支持内网、自签名 TLS、SVG、任意端口或任意响应正文，也不复用音源配置的 HTTP/SOCKS 代理。TUN/fake-IP DNS 应为该进程返回真实公网解析结果，不应放行保留地址规避策略。默认重定向封面、音频代理及 WebDAV 不受这一独立客户端策略影响。
- 元数据清理后磁盘文件可能不变，这是空闲页保留供复用。压缩必须另行在维护窗口确认执行。
- 推送触发 Actions 检查及符合分支条件的镜像发布，不代表已有容器已部署更新。

- Node 26.10.0：53 项单元测试通过。
- Chromium：42 项验收通过，包含新增用户模块事件委托和清理／压缩分开确认，以及原有播放、Range、会话隔离、草稿竞态、听歌统计和移动端检查。证据目录为 `/tmp/lxsc-hardening-browser-verified`，可被系统临时目录清理策略移除。
- 本地使用锁定 Playwright 1.58.2 配合已安装的 Chromium headless shell 1243，通过 `LXSC_CHROMIUM_PATH` 指定。尝试安装其默认 Chromium 1208 时下载／解包超时，因此未把默认配套浏览器记录为已验收；CI 在 Ubuntu 24.04 安装锁定版本对应浏览器，以远程实际结果为准。

开发时真实浏览器发现新增 I/O 中间件主动设置过去的读取截止会取消连接上下文，导致连接复用后的分块响应被截断；已移除此行为并增加 50 次真实 HTTP 响应完整性回归。扩充浏览器用例后也发现测试控制会话超过每用户十个会话上限会被正常淘汰；测试现于每项验收前重新建立控制会话，没有放宽服务端会话限制。

## 合成缓存基准

Linux/amd64、i5-13600K、Go 1.27.1，固定每批 100 首合成歌曲，100 次迭代、重复三轮：

| 路径 | 每批耗时 | 每批分配字节 | 每批分配次数 |
|---|---:|---:|---:|
| 原有落库行准备路径 | 354–440 µs | 51,832–51,907 B | 1802 |
| 纯内存缓存路径 | 109–117 µs | 2,628 B | 201 |

这是缓存局部基准，不包含第三方请求、网络或播放，不据此声称整体搜索提升相同倍数。其他既有搜索／直链／统计基准可由同一命令复现，CI 保存结果用于趋势比较，不设置固定机器耗时门槛。

```bash
bash scripts/check.sh --race
GOTOOLCHAIN=go1.27.0 bash scripts/check.sh
GOTOOLCHAIN=go1.27.0 node scripts/licenses.mjs --check

go test ./internal/music ./internal/db -run '^$' \
  -bench 'Benchmark(TemporaryCache|ConcurrentSearch|PersistentURLCacheHit|ListeningWithUserLookups)$' \
  -benchmem -benchtime=100x -count=3

npm --prefix tests/web ci --ignore-scripts
node tests/web/node_modules/playwright/cli.js install chromium
node tests/web/browser.cjs
```
