# 音源自动更新

管理员在「音源」页通过 URL 导入脚本时，来源地址会一同保存，默认开启每日自动更新，可在导入时关闭。上传脚本和以前导入的音源保留现有状态；管理员可以打开对应卡片的「更新设置」，补填来源 URL 后开启。

自动更新始终使用管理员保存的 HTTP(S) 地址，沿用服务配置的出站网络。脚本中的主页或更新提示不会自动替换来源。下载最多 8 MiB，单次下载期限为 60 秒。

## 检查计划

- 每天北京时间凌晨 3:00 检查，不受进程所在时区影响。
- 服务启动时补查最近一次过期计划。错过多天只检查最新脚本一次。
- 停用音源或关闭每日更新时暂停自动检查；重新启用后补查已过期的计划。
- 失败后最多再重试两次，间隔依次为 5 分钟、30 分钟；三次均失败后等待次日计划。等待时间和已执行次数保存在数据库，重启后继续。
- 后台和手动检查共享两个执行名额，同一音源同时只执行一个检查。服务退出时取消下载、验证任务，并等待工作结束后关闭数据库。

## 替换与结果

按脚本内容比较，先去除 UTF-8 BOM；版本号相同但内容有变化也会更新。内容未变化时记录本次检查，保留脚本更新时间、运行实例和有效直链缓存。

新内容先在独立候选实例中执行，验证初始化事件和支持的平台、动作、音质声明。验证成功并保存后才切换实例，保留原音源 ID、管理员名称、启用状态和来源配置；更新成功使后续播放重新使用当前音源状态解析直链。初始化验证不保证所有平台或曲目都能播放。

下载、执行、初始化或保存失败时，旧脚本和运行实例继续保留。检查结果会显示失败原因；源端响应正文和带凭据的地址不会作为失败提示输出。修改来源、停用、删除或显式重载会取消在途更新，旧请求不能覆盖新的设置。

音源卡片显示最近检查时间、脚本更新时间、检查结果和下次检查时间。管理员可以随时「立即检查更新」，关闭每日更新或停用音源时也可手动检查；停用状态会保留，新脚本不会因此启用。

## 管理接口

| 接口 | 行为 |
| --- | --- |
| `POST /api/admin/sources/import` | 接收 `url`、可选 `name`、可选 `autoUpdate`；省略更新开关时默认开启 |
| `PUT /api/admin/sources/{id}` | 支持已有名称、启用、脚本字段及新增的 `url`、`autoUpdate`；开启更新需填写来源 |
| `POST /api/admin/sources/{id}/check` | 手动检查并在验证通过后更新，失败使用 502；重复在途检查使用 409，执行名额已满使用 503 |
| `GET /api/admin/sources` | 返回来源、开关、检查结果和更新时间，不返回脚本正文 |

所有接口沿用管理员网页登录权限。来源配置和检查状态随 SQLite 快照备份；旧音源缺少来源地址时不会从脚本主页推测 URL，也不会虚构以前的更新记录。
