# 热点路径优化验收

2026-10-01。所有验证使用临时数据库、合成歌曲与本机测试服务。

## 修改范围

- API Key 查询同时读取最近使用时间，只在超过五分钟窗口时提交条件更新 SQL。每次认证仍实时检查密钥、有效期和用户；不缓存认证结果。
- 创建与替换歌单共用批量写入，每批 300 首、900 个参数。2000 首最多七次插入，保持事务、顺序、重复项、权限及草稿冲突保护。
- 直链缓存命中的使用时间每首每分钟最多排队一次，后台每秒合并为一个事务；队列不超过缓存容量。正常关闭冲刷队列，后台故障自动退回内存缓存并标记旧持久库不可复用。使用时间只单调更新现存记录，不创建直链，因此迟到更新不能复活已删除直链。直链保存、失效和配置代次仍使用原同步顺序。性能计数记录实际后台落盘时间，不把排队耗时当成磁盘耗时。
- 歌单排序移动现有 DOM 行，只更新受影响区间的序号与按钮，保留重复歌曲、焦点和播放标记。全量加载仍沿用行复用机制，本轮不引入虚拟列表。
- 概览、音源、日志与备份通过两个 ES Modules 按需加载，依赖由工厂参数显式传入。保留其他页面现有接口，逐步迁移。动态模块脚本继续使用内容版本和 SRI，未放宽 CSP。网络错误可重试，切换路由或退出后迟到加载不触发旧页面数据请求，重复进入不重复绑定事件。
- 新增一字、两字、热门三字、稀有长词与深分页搜索基准，以及逐首／批量写入对比，并加入 CI 基准附件。没有增加新搜索索引或改变匹配语义。

使用时间为可重建的 LRU 提示。异常退出可能丢失尚未冲刷的提示，队列满时可丢弃新提示；不影响已保存的直链内容、绝对有效期或业务数据。

## 合成基准

Darwin/arm64，Apple M6，Go 1.27.0；每组 20 次、三轮，准备数据不计时。同一数据库对比 2000 首歌单删除后重建，包含事务提交。

| 路径 | 耗时 | 分配字节 | 分配次数 |
|---|---:|---:|---:|
| 逐首写入 | 6.46–6.48 ms | 约 557 KB | 21501 |
| 批量写入 | 4.99–5.03 ms | 约 606 KB | 7649–7650 |

耗时减少约 23%，分配次数减少约 64%，但分配字节数增加约 9%。这些是局部合成测量，不代表真实音源或整站性能提升幅度。

十万首数据下，稀有一字查询约 13.6–14.0 ms，稀有两字约 14.4 ms，稀有长词约 0.166–0.169 ms；所有记录都命中的三字 FTS 查询约 131 ms。结果说明索引收益取决于命中率，高命中查询计划值得后续单独评估，不能仅以词长推断收益。

