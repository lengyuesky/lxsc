# ChKSz API 只在全部音源和平台确认失败后兜底

音源脚本全部失效或曲目在所有脚本上都取不到时，播放只能报告失败。选择接入 ChKSz 公共音乐 API 作为选源的最后一级：顺序为已验证缓存 → 所在平台全部音源与音质 → 其它平台上的同一首歌 → ChKSz 兜底。兜底不是音源脚本，不参与 [0005](0005-playback-selection-single-race.md) 的并发竞速，也不计入音源调度与评分；它给出的地址与音源结果一样，必须通过真实音频验证才交付。

免费额度按次计（每日 400 次），因此兜底依次而不并发：先试所在平台（网易云、QQ 音乐、酷狗），接口明确表示该档不可用时再试 320k，仍失败才搜索其它平台上最匹配的一首受支持曲目；酷我、咪咕的曲目直接走后者。取到的地址单独缓存 10 分钟（不持久化、不进入音源直链缓存），HEAD 与 GET 共用一次调用；密钥失效时暂停 10 分钟，限流时按 Retry-After 或 5 分钟暂停，更换密钥立即恢复。音源与平台已完整确认失败、由兜底播放成功的曲目，30 分钟内重播直接走兜底，与换平台结论相同；被预留时间截断、没有结论的选源不记。

代价有两项。一是启用兜底后音源与换平台选源最多只用 22 秒（总上限 30 秒，留 8 秒兜底），慢音源的失败路径更早被截断，截断后仍会兜底。二是播放失败的含义扩展为"连兜底也失败"，失败类别仍报告音源的结论，兜底失败只记入诊断与播放日志的 `fallback_api` 阶段。

密钥只写不读：设置接口和调试接口只公开是否已配置，调试凭据不能修改；返回地址若携带密钥则拒绝使用，防止 302 交付把密钥交给客户端。
