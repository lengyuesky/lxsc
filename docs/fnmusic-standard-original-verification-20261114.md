# 飞牛标准音质使用原始音频验证

记录日期：2026-11-14。原版客户端实测基线为 `57766b5` 加本轮修复；提交前接上远端 `14033bb` 后另行重跑自动回归。生产服务尚未更新。

## 问题与处理

原版飞牛音乐在移动网络偏好为标准时，会先调用 `POST /music/api/v1/track/transcode`。原实现固定返回 501，客户端随后提示已跳过无法播放的歌曲。本轮使用隔离合成账号重新观察到这一失败。

客户端随后读取固定的 `track/hls/{guid}/preset.m3u8`。直接在这个路径重定向到原始 WAV 会让客户端把 `RIFF` 文件头当作清单 URI，不能播放。当前实现提供只有一个完整原始媒体项的兼容清单，指向既有 `track/stream?guid=…`，音频正文由共享媒体服务交付，不编码、不切片、不缓存整首音频到服务器。

准备接口返回 `data.status=ready` 和 `transcoded=false`，表示原始播放清单可用；没有转码任务。请求中的 `output.codec`、`output.bitrate`、`output.start` 不改变原始音频。心跳和退出只确认当前曲目的访问权限，不分配任务或记录收听。

清单、准备、心跳、退出及媒体入口各自复核当前账号权限。客户端参数不能覆盖用户的取链音质或管理员的交付模式。实际取链、内容解码验证、302、代理、HEAD、Range/If-Range 继续使用共享媒体服务；下载转码仍返回 501。

## 原版客户端实测

客户端为本机已安装的飞牛音乐 1.0.3，构建 103006，`com.trim.music.ios`，iOS-on-Mac。服务、观测转发器和合成音频上游均仅监听 `127.0.0.1`；没有使用生产账号、真实歌曲或真实在线音源。最终复验运行重新构建的修复代码，观测转发器原样透传请求与响应。

| 检查 | 观察结果 |
| --- | --- |
| 客户端偏好 | Wi-Fi 原始、移动网络标准、下载原始；本轮没有改动这些偏好 |
| 原始 MP3 | 标准设置成功播放；原版播放器观察到 `00:27 / 00:45` 与暂停按钮 |
| 原始 FLAC | 标准设置成功播放；暂停在 `00:16 / 00:45`，拖到 `00:37` 后恢复播放 |
| 切歌与自然结束 | 手动切歌触发重新准备和进度重置；自然结束后自动切换到另一曲目 |
| 直链 | 原始 stream 返回 302，客户端从合成上游完整读取 MP3 的 1802492 字节及 FLAC 的 705711 字节 |

合成 MP3、FLAC 由测试期间独立生成。服务端使用 FFmpeg 验证有界起始音频片段，播放交付没有启动编码任务。完整原始字节的自动比较与客户端实际读取是两类证据；没有录制输出设备声音，不能声明输出链路的无损质量。

## 兼容边界与清理

- 原版 App 可能仍按标准偏好显示“转码 / OPUS”及偏好码率，实际交付仍是原始 WAV、MP3 或 FLAC。这是客户端显示限制，不能将该标签作为编码证据。
- 单个原始媒体项不承诺所有 HLS 客户端或所有容器都兼容。当前原版验证只覆盖该 Mac 和版本、上述合成音频；iPhone/Android 真机流量、真实 CDN、弱网、远端未缓冲拖动及后台播放需要单独验收。
- 标准设置使用原文件流量，不提供节省流量的转码。仍沿用 lxsc 用户默认音质和降档策略，不保证最高档。时长元数据缺失时返回明确错误，客户端须选择原始音质播放。
- 已停止本轮两个隔离服务及其上游，内存会话随进程退出失效，临时数据库、构建二进制和独立生成的测试音频已清理。客户端恢复为测试前的 `127.0.0.1:55829`、`alice`、空密码、HTTPS 关闭、未记住密码的连接页；音质偏好保留原值。为保留既有记录和缓存，没有清空 App，新增的本机合成连接记录仍保留。
- 运行证据位于忽略目录 `tmp/fnmusic-standard-original-20261114.4arJog/`：基线和原型 `requests.ndjson`、原版复验 `requests-final.ndjson`、合成上游 `media-final.ndjson`、首轮自动回归 `check-race.log`、接入远端后的自动回归 `check-race-rebased.log`。客户端进度和操作来自本轮原版工具观察，没有声称已保存原版截图文件。
